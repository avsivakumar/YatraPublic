# Message Protocol

Yatra uses one envelope, `YatraMessage`, for browser, engine, and agent messages.

## Envelope

```json
{
  "messageId": "01K4V9Z7Y3J7NQX7F8EJ9P4W2A",
  "conversationId": "01K4V9Z20RB7NQGJPM5S7ZZ8Z1",
  "type": "user.text",
  "source": "ui:current-conversation",
  "destination": "engine:inbound",
  "createdAtUtc": "2026-09-10T17:30:00.0000000+00:00",
  "inReplyTo": null,
  "expectsReply": false,
  "payload": {}
}
```

Fields:

- `messageId`: ULID string generated by the sender.
- `conversationId`: ULID string for conversation isolation.
- `type`: known message type.
- `source`: trusted source assigned by server or adapter.
- `destination`: trusted destination assigned by server or adapter.
- `createdAtUtc`: authoritative message timestamp. Browser submissions receive a server timestamp.
- `inReplyTo`: message ID that caused this message, when applicable.
- `expectsReply`: true only when the message creates a pending reply.
- `payload`: type-specific JSON.

## Message Types

- `user.text`: browser user text.
- `agent.text`: agent text output.
- `form.request`: agent asks the UI to render a form.
- `form.response`: browser responds to a form.
- `status`: reserved status message type.
- `error`: application-level Yatra error.

## Browser Submit API

`POST /api/conversations/{conversationId}/messages`

The browser submits:

```json
{
  "messageId": "01K4VA1M8K67YXT2TY5KFG9V1A",
  "type": "user.text",
  "inReplyTo": null,
  "payload": {
    "text": "hello"
  }
}
```

Only `user.text` and `form.response` are accepted from the browser. The server rejects invalid ULIDs, unsupported types, invalid envelopes, and conversation mismatches.

The server affixes:

- `conversationId` from the route.
- `source = ui:current-conversation`.
- `destination = engine:inbound`.
- `createdAtUtc = DateTimeOffset.UtcNow`.
- `expectsReply = false`.

A valid submission returns `202 Accepted` with the following body. This confirms queue acceptance, not business success. The UI checks the ID and status before locking the form.

```json
{"messageId":"01K4VA1M8K67YXT2TY5KFG9V1A","status":"accepted","replayed":false}
```

Identical retries return acceptance with `replayed: true` without re-enqueueing. Reusing an ID with different conversation, type, correlation, or payload returns HTTP 409 with `code: response_conflict`, a safe `message`, and `retryable: false`. JSON property order is insignificant; server timestamps are excluded. The durable inbox is committed before acknowledgement, and unfinished work and pending replies recover on startup. One engine process exclusively owns the storage folder. See [Persistence](Persistence.md) for recovery and adapter idempotency guarantees.

HTTP errors may include `message`, `retryable`, and `fieldErrors` (field ID to message). HTTP 401/403, 409, and 410 disable resubmission. Validation errors permit correction. Timeouts, network failures, malformed acknowledgements, and temporary server failures preserve values and permit transport retry. Decisions do not depend on message text.

Form lifecycle: `open -> submitting -> submitted` on durable HTTP acceptance. A correlated agent confirmation changes `submitted` to `completed` (or `cancelled` for cancellation). A retryable asynchronous error returns it to `open`; a terminal error locks it. An SSE business outcome received before the HTTP promise settles takes precedence over that acknowledgement. Replayed `form.response` messages establish acceptance, never business completion.

## SSE API

`GET /api/conversations/{conversationId}/events`

The response is `text/event-stream`.

When a stream opens, the server replays stored conversation messages, then continues with live events. `Last-Event-ID` or query parameter `lastEventId` resumes after a known message ID; an absent or unknown cursor replays all history. Clients deduplicate by ULID before applying messages or form outcomes.

The UI closes the previous EventSource before retrying at 1, 2, 4, 8, 16, and 30 seconds. Exhaustion displays one connection error and retry button. A connection stable for 30 seconds resets the budget. Closing the UI stops retries. Forms remain available over HTTP during SSE recovery, with drafts and acknowledged state preserved.

Initial comment:

```text
: connected
```

Heartbeat comment:

```text
: heartbeat 2026-09-10T17:30:15.0000000+00:00
```

Message event:

```text
id: 01K4VA8GBF3MCP6BQY0MSQR8WE
event: agent.text
data: {"messageId":"01K4VA8GBF3MCP6BQY0MSQR8WE",...}
```

Yatra application errors may use `event: error`, so browser clients should handle named application error events separately from EventSource transport failures.

## Text Payloads

`user.text` and `agent.text` use:

```json
{
  "text": "message text"
}
```

## Form Request Payload

`form.request` uses:

```json
{
  "formId": "contact",
  "formVersion": "1.0",
  "title": "Contact",
  "description": "Optional helper text",
  "submitLabel": "Send",
  "cancelLabel": "Cancel",
  "fields": [
    {
      "id": "name",
      "type": "text",
      "label": "Name",
      "required": true,
      "minLength": 1,
      "maxLength": 100,
      "pattern": null,
      "placeholder": "Your name",
      "options": null
    }
  ]
}
```

Supported field types:

- `text`
- `textarea`
- `number`
- `date`
- `select`
- `checkbox`
- `datetime`
- `multiselect`
- `display`
- `hidden`

Supported constraints:

- `required`
- `minLength`
- `maxLength`
- `min`
- `max`
- `pattern`
- `options`
- `integerOnly` for numbers
- `minSelections` and `maxSelections` for multiple choice
- `minDate` and `maxDate` for inclusive date/date-time boundaries

`formVersion` is the existing contract version: Version 1 accepts `1` and numeric `1.x` versions; unknown major versions fail closed. Agents must emit documented camelCase property names and lowercase types/actions. The browser is case-sensitive. Legacy .NET DTO deserialization remains case-insensitive; browser response payloads are checked using documented names.

Fields render in supplied order. IDs must be nonempty and unique, and labels nonempty. Optional `required`, `disabled`, and `readOnly` default to false. `initialValue` defaults to empty string, false for checkbox, or empty array for multiselect. `helpText`, constraints, and placeholder are optional; null optional metadata is absent. Inapplicable constraints, invalid patterns, contradictory bounds, invalid initial values, missing/duplicate options, and unknown types make the entire form unavailable, including optional fields.

| Type | Submitted value |
| --- | --- |
| text, textarea | Exact string, without trimming |
| number | Finite JSON number |
| date | Calendar date `YYYY-MM-DD` |
| datetime | ISO local date-time `YYYY-MM-DDTHH:mm[:ss[.fraction]]`, without timezone conversion |
| checkbox | Boolean; required confirmation must be true |
| select | Option value string, never its label |
| multiselect | Array of unique option value strings |
| display | Omitted; initial text or label is displayed |
| hidden | Supplied string, finite number, boolean, or string array |

Blank optional scalar input uses an empty string. Disabled/read-only values are included and validated. Hidden values are explicitly returned by this contract but must not be trusted for identity or authorization. Submit and optional cancel are declared through `submitLabel` and `cancelLabel`; no executable actions are accepted. Cancel bypasses value validation and sends `{}`. Text constraints apply to the exact submitted string. Empty optional scalar values bypass constraints; selection counts apply to empty arrays. Application validation remains authoritative.

## Form Response Payload

`form.response` uses:

```json
{
  "formId": "contact",
  "formVersion": "1.0",
  "action": "submit",
  "values": {
    "name": "Asha"
  }
}
```

Actions:

- `submit`
- `cancel`

`inReplyTo` is the original `form.request` message ID. Transport retries reuse the same response `messageId` and payload. Changed values/actions, or a new attempt after explicit retryable asynchronous rejection, use a new ULID and set optional payload `replacesResponseId` to the previous response ULID. The original `inReplyTo` remains unchanged. A transport retry never mutates payload properties.

The engine validates the response against pending-reply metadata recorded when the form was originally requested. It rejects mismatched form IDs, mismatched versions, duplicate responses, cross-conversation responses, expired replies, invalid values, and malformed payloads.

Cancellation may omit normal field values.

## Error Payload

`error` uses:

```json
{
  "code": "requester_unavailable",
  "message": "The response could not be delivered. Please try again.",
  "retryable": true,
  "relatedMessageId": "01K4VA1M8K67YXT2TY5KFG9V1A"
}
```

Common codes include:

- `invalid_message`
- `invalid_form_response`
- `pending_reply_not_found`
- `pending_reply_expired`
- `conversation_mismatch`
- `duplicate_response`
- `requester_unavailable`
- `llm_unavailable`
- `invalid_return_path`

Clients should reopen forms for retryable errors that reference the pending response or original form request, and keep forms closed for terminal errors.
